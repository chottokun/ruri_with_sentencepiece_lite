# ベンチマーク・性能評価レポート

本ドキュメントでは、[`Google SentencePiece Lite`](https://google.github.io/sentencepiece/lite/) および ONNX Runtime を用いた軽量推論環境（本実装）と、標準的な `transformers` + `PyTorch` 構成との性能比較検証結果をまとめます。

---

## 1. トークナイザー単体性能（前処理スループット）

日本語テキスト 10,000 件を連続でトークナイズした際の所要時間、スループット（処理件数/秒）、および 1 件あたりの平均レイテンシを測定しました。

### 測定結果 (10,000 件)

| トークナイザー実装 | 10,000 件所要時間 | スループット (Throughput) | 1件あたり平均レイテンシ | 高速化倍率 |
|---|---|---|---|---|
| **Hugging Face Fast Tokenizer** (Rustベース) | 455.03 ms | 21,976.5 sent/s | 45.50 µs | 1.0x (基準) |
| **SentencePiece Lite (本実装)** (C++20 Zero-copy mmap) | **33.97 ms** | **294,395.5 sent/s** | **3.40 µs** | **約 13.4 倍 高速** ⚡ |

### 技術的解説
* **Zero-copy mmap**: FlatBuffers 形式（`.spm.fb`）を採用することで、ファイルからのメモリコピーおよびパースオーバーヘッドを完全に排除しています。
* **CPU ボトルネックの解消**: GPU 推論環境であっても前処理（トークナイズ）は CPU が担当するため、従来構成ではトークナイズ待ち（GPUの遊休）が発生していました。SentencePiece Lite により 1 文わずか **3.4 マイクロ秒** で処理され、大規模バッチ処理時でも CPU 前処理がボトルネックになりません。

## 2. テンソル推論性能 (ModernBert / 30m)

バッチサイズ 32、系列長 64 における純粋なモデル推論時間（CPU環境）の比較です。

| 実行ランタイム | 1バッチ (32系列) あたりの推論時間 | 備考 |
|---|---|---|
| **PyTorch 2.14** (CPU) | 291.24 ms | PyTorch JIT / C++ バックエンド |
| **ONNX Runtime** (CPU / FP32) | **270.27 ms** | ORT レベル全最適化有効 |

## 3. ハードウェア適応型推論（Pascal vs Ampere以降）

本リポジトリのラッパー（`ruri_v3_lite.py`）は、実行環境の GPU 世代（CUDA Compute Capability）を `ctypes` 経由で自動判別します：

| 実行環境 | アーキテクチャ | 選択されるモデル | 最適化の理由 |
|---|---|---|---|
| **CPU のみ** | x86_64 / ARM | `model.onnx` (FP32) | CPU ネイティブ演算 |
| **GTX 1080 / 1060** 等 | Pascal (CC 6.1 < 7.0) | `model.onnx` (FP32) | Pascal 世代は FP16 演算器が弱く、FP32 の方が高速 |
| **RTX 3060 / 4090 / A100** 等 | Ampere / Hopper (CC ≥ 7.0) | `model_fp16.onnx` (FP16) | Tensor コアの活用により **スループット約2倍・VRAM消費半減** |
